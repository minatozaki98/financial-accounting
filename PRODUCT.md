# Product

## Register

product

## Users

The primary users are research reviewers, assessors, and developers demonstrating the ASP.NET Core financial-accounting API. They need to sign in with a role, inspect live accounting data, exercise allowed operations, and capture credible evidence of authentication, RBAC, reporting, and auditing behavior.

## Product Purpose

Financial Accounting API Demo is a local research application that makes the existing API surface observable and testable through an authenticated web interface. Success means that a reviewer can understand the current role, data state, allowed actions, and returned financial values without needing Swagger or raw JSON.

## Brand Personality

Quiet, precise, dependable. The interface should feel like an accounting workspace used to inspect real operational data: calm enough for extended review, exact enough for financial values, and polished enough to support a final report.

## Anti-references

Avoid marketing-style hero layouts, oversized dashboard cards, decorative gradients, noisy visual effects, and consumer-finance styling. Avoid hiding essential financial detail behind excessive modals or visualizations. The application must not resemble a generic AI-generated SaaS landing page.

## Design Principles

1. Put the ledger first: tables and financial detail are the primary interface, not decoration.
2. Make authority visible: current role, permitted actions, and restricted surfaces should be easy to understand.
3. Prefer progressive disclosure: keep lists scan-friendly and reveal line or balance detail when requested.
4. Keep evidence credible: live API status, report parameters, and audit trails should read as verifiable operational evidence.
5. Preserve user flow: consistent controls, concise feedback, and stable layouts help reviewers move through demonstrations quickly.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast and keyboard-operable controls. Do not rely on color alone for status. Provide visible focus treatment, labelled controls, readable table structures, reduced-motion support, and responsive fallback for narrow screens.
