# 2.17 Framework Context: ASP.NET Core, Spring Boot, and Express.js

The financial accounting system studied here already uses ASP.NET Core 8, C#, and SQL Server. Spring Boot and Express.js are relevant alternatives in the literature, but this thesis does not implement them. A framework migration would change the application and its data-access behavior at the same time as the proposed fixes, making the branch-based before/after study harder to interpret. The published comparisons below therefore provide **context for the stack decision**, not measurements of this financial API.

Szewczyk and Skublewska-Paszkowska (2025) implemented the same JWT-protected CRUD API in ASP.NET 8.0, Spring Boot 3.3.2, Express.js 4.19.2, Laravel, and Django REST Framework, using matching MySQL data and Docker deployments on Azure. Across their chosen scenarios, ASP.NET had the shortest response times in most cases and one of the smallest container images. Spring Boot was close in several measures; Express.js showed comparatively balanced CPU and memory use. Their hypothesis that Express.js would be the fastest for small result sets was rejected because ASP.NET and Express.js were often similar. The authors also found that ASP.NET required more source code than some alternatives. Their study did **not** evaluate security or dynamic scalability and used a different database and workload, so its latency rankings cannot be copied into the results for this accounting API.

Grzeszuk and Miłosz (2025) directly compared Spring Boot and ASP.NET Core CRUD applications. Their results were mixed by operation: Spring Boot performed better for CREATE requests and joined queries, ASP.NET Core performed better for DELETE and some CPU measures, and basic GET times were similar. This is a useful counterpoint to an unconditional claim that one framework is always faster. Their PostgreSQL CRUD workload and deployment differ from this study's SQL Server financial reporting workload, so their numbers cannot predict our p95 or p99 measurements.

The literature supports ASP.NET Core as a credible, performant framework for the existing API while showing that alternative stacks have workload-specific strengths. This study therefore keeps ASP.NET Core as the **only implemented and measured stack**, evaluates its frozen before/after source revisions, and limits Spring Boot and Express.js to this literature comparison. It makes no claim that the JMeter improvement would be the same on either alternative stack.
