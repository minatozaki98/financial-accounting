# Chapter 2 support for the controlled JMeter comparison

The current `Document/outputs/final-report.docx` Chapter 2 has sections 2.1–2.15. Section 2.5 addresses Web API issues and section 2.15 cautions against treating SonarQube counts as direct proof of fewer defects. It has no dedicated literature review of reproducible cloud performance measurement, latency tails, or cloud VM variability. Add a short section 2.16 before using those claims in the results chapter.

The exact JMeter scheduler and Docker limit settings should cite their official documentation in the methods section. The papers above justify the experimental interpretation and reporting choices. User counts, performance thresholds, and timing buffers are this study's own choices; the post-scoring correction from JTL-bin completeness to thread-lifecycle concurrency proof must be disclosed separately. No paper should be credited with those exact values or that correction.

## Brief alternative-stack context for Chapter 2.17

The existing report's Chapter 2 had no direct empirical comparison of ASP.NET Core with the two secondary stacks named in the paper, Spring Boot and Express.js. The following publisher-hosted, DOI-registered papers support a **literature comparison only**. Neither paper measured this financial accounting API, and neither justifies building another implementation for this thesis.

[doi:10.35784/jcsi.7041](https://doi.org/10.35784/jcsi.7041). | The authors implemented comparable JWT/CRUD APIs in ASP.NET 8.0, Spring Boot 3.3.2, Express.js 4.19.2, Laravel, and Django REST Framework using matching MySQL data and Azure Docker deployments.
