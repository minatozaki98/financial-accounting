# Excluded controlled JMeter attempts

The study keeps raw files for failed or interrupted attempts. The original JTL-bin concurrency rule was later corrected as described in [validity-amendment.md](validity-amendment.md). No attempt in this table is selected or rejected based on a favorable latency value; only complete, valid before/after pairs enter the three-repeat comparison.

| Attempt | Observation | Exclusion reason | Follow-up |
| --- | --- | --- | --- |
| `p50-r1-before-a1` | The 50-user JMeter run completed with zero reported request errors. Its JTL and JMeter log were copied locally. | The target host collector did not start because the runner created its results directory only on the generator. The required target CPU/memory record is absent, so resource validity cannot be established. | Fixed the shared runner in commit `340d108`; a focused test and live collector smoke passed on both VMs. Rerun the entire before/after pair as attempt `a2`. No source build, JMX file, dataset, or resource cap changed. |
| `p500-r3-before-a1` | The baseline completed with 500 distinct users, zero errors, 119 observed exact 500-user JTL bins, and no generator throttling. One five-second request bin at 405–410 seconds was empty. | Version 1 initially rejected the missing JTL bin. Version 2 thread lifecycle analysis later proves all 500 users stayed active through the scored hold, but no matching after side was run, so it is still an incomplete pair. The cause of the request stall is unverified. | Retain raw evidence and disclose the post-scoring analysis correction; do not choose this baseline merely because its latency is favorable. Run a new complete pair under the amended gate. |
| `p500-r3-before-a2` | The previously missing bin had 1,348 partial JTL samples, all showing 500 users. The run was stopped before completion and no matching after side was started. | During the scored hold, an operator-initiated copy of the live JTL from the generator remained active longer than expected. Public-network transfer and SSH encryption could interfere with the load generator, so this attempt is excluded independently of its visible request behavior. The copy was stopped and the JMeter container and both metric collectors were terminated by their verified experiment identities. | Rerun the **entire** p500 repeat-3 pair as attempt `a3` without any in-run artifact transfer. No source image, JMX, dataset, cap, or validity threshold changed. |
| `p500-r3-before-a3` | The baseline completed with 500 distinct users, zero errors, 118 observed exact 500-user JTL bins, and no generator throttling. Request bins at 270–275 and 345–350 seconds were empty. | Version 1 initially rejected the empty request bins. Version 2 thread lifecycle analysis later proves all 500 users stayed active through the scored hold, but no matching after side was run, so it is still an incomplete pair. The cause of the stalls is unverified. | Retain raw evidence and run a new complete before/after pair under the amended gate, without selecting among the earlier baselines by performance. |

No attempt in this table is used in the three-repeat comparison.
